# Improve model selection, reading, and edited-prompt branches

Model selection now groups browser-local favorites and recently selected models ahead of the rest of the Provider catalog. Optional capability, minimum-context, and USD-rate filters use advertised fields only; missing fields cannot satisfy a corresponding filter. The current selection remains visible in the closed control even when a filter excludes it. Saved model combinations contain a name and one to four Provider/model identifiers. Applying one validates the entire set against current configured Providers and available catalogs, then saves the Active Model Set in one settings command. Unavailable entries are shown without silently substituting another model. These preferences contain no keys or conversation content and are bounded in browser storage; unavailable storage falls back to the current session.

Assistant headers retain model identity and a compact verification summary. One Response details dialog combines observed Generation Metrics, the immutable Provider Snapshot and Privacy Notice, and the existing verification lanes/reports. Failed or incomplete verification remains visible in the header. This extends ADR-0008, ADR-0023, ADR-0032, and ADR-0034 without reclassifying evidence or hiding an error behind the dialog.

Reading follows the latest answer until an explicit user scroll/navigation pauses it. Resize observation includes the message content, and a visible text block anchors the viewport during reasoning folds, verification transitions, and streamed Markdown layout changes. The return-to-latest action reports how many answers gained text while following was paused. It resets after returning or submitting a new turn. Counts are presentation state and do not enter history.

Editing a saved terminal user turn creates a separate Conversation. Its inherited history copies only the Selected Answers referenced by that turn's immutable Context Snapshot, excluding that turn's old answer and all later turns. Copied messages, Generation records, selected dispositions, verification records, context references, and source snapshots receive independent local ownership; copied evidence still describes its original response and is not reverified by copying. Deleting the original Conversation cannot mutate the branch. The branch banner and exports identify its source. Schema 19 adds `conversation_branches`; source identifiers are provenance strings rather than foreign keys into deletable history.

The edit command uses the existing message submission endpoint with optional `edit_of_batch_id`. Chat validates the source, reuses that turn's exact saved attachments without reparsing, applies current System Prompt/generation settings, and resolves the chosen nonempty subset of the current Active Model Set. Persistence creates the copied prefix and new pending Batch atomically after the existing idempotency check. Failure rolls back the branch; a repeated client request returns the existing Batch. The original history, context choices, and saved configuration remain unchanged. HTTP remains an adapter, Chat owns inference and selection checks, and persistence owns copying and transactions. Ordinary streams and browser-controlled inference use the returned branch Batch and its authoritative context. The global one-active-Batch rule still applies.

Generation waiting text distinguishes first text, reasoning, final text, and response verification, and shows elapsed time. Fifteen seconds without activity adds a bounded delay message and a stop action. Failures retain safe diagnostics and offer applicable retry, model choice, editing, or Provider settings actions. Model choice affects future submissions; ordinary retry still reuses the original target and immutable context. No failure action automatically resends content, changes privacy requirements, or rotates credentials.
