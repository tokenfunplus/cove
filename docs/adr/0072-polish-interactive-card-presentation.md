# Polish interactive card presentation

Extend ADR-0020's motion policy to user-driven card reordering and short local content reveals. Keep ADR-0063 through ADR-0068's DSL, validation, persistence, conflict handling, and explicit continuation semantics unchanged.

The renderer derives a presentation label from registered component types: choices, quizzes, itineraries, budgets, and editing. Labels and visual recipes are owned by Cove, not model-provided CSS or executable content. Semantic theme tokens cover light/dark skins; Tailwind slot recipes own component styling. Metadata uses a compact footer with expandable destination details. The footer has its own container-aware grid: fixed status, question, and details slots keep controls anchored while autosave copy changes. Narrow cards use two rows without tying any column width to save-status text. Missing choice legends use readable single/multiple-choice prompts rather than exposing state binding names. Ask about this focuses its newly revealed question field only on that explicit action; opening/closing the expanded dialog retains the shared focus-restoration behavior. Saved definitions require no migration. Expanded cards use a centered, width-bounded dialog at every breakpoint, with viewport margins and an internally scrolling body. This replaces the wide-screen edge-aligned expansion; Escape, focus containment, focus restoration, and shared card state are preserved. The expanded panel measures and retains its opening height until closed, bounded by 85dvh. Its scroll body reserves a scrollbar gutter; errors/retry controls and Close remain outside that scroll body. Save failures and validation messages shrink the internal body instead of moving or resizing the centered panel.

Ranking retains HTML drag/drop and labelled move buttons, adding a pointer-captured handle for mouse, pen, and touch and Arrow Up/Down keyboard control. Reordering animates displaced rows for 220ms using measured local layout, with no animation on initial load or history restoration. The OS reduced-motion preference disables these animations. Only the active pointer can finish or cancel its reorder; releasing a secondary touch does not interrupt it. Controls keep their DOM identity and keyboard focus. Animation does not trigger state writes or model requests; existing local edits and explicit continuation remain authoritative.

Cards use a tinted illustrated header and high-contrast filled selection surfaces rather than relying on border changes alone. Choice selection transitions the check mark, fill, and elevation. Tailwind 4 uses individual scale/rotate/translate properties, so transition recipes explicitly include them; dragged rows visibly lift while displaced rows move. Text-bearing choice surfaces and action buttons do not scale or translate on hover/press; only decorative check marks and arrow icons transform. Selection summaries remain available to assistive technology without inserting a visible row that re-centers the expanded dialog. Choice press/selection feedback and short feedback/reveal entrances follow the shared reduced-motion policy. Slider input stays immediate; the aggregate allocation bar and a decorative percentage ring transition to their new values. The existing labelled progress element remains the accessible source of allocation status; the ring does not duplicate announcements. Focus highlights connect editing controls to the text preview without changing its content. Text editing and preview remain plain escaped text. No decorative animation loops are introduced.

Validation covers pointer and keyboard reordering, focus/announcement preservation, animation cancellation, reduced motion, locked cards, existing card persistence and continuation, production browser acceptance with stable text geometry during pointer presses and frame-by-frame footer bounds across delayed autosaves and panel bounds across save failure/retry and observed selection and allocation transition events, and narrow/light/dark presentation checks.
