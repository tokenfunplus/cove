# Keep history search and draft navigation local

History search goes through the authenticated HTTP adapter, Chat query facade, and SQLite persistence. It matches literal case-insensitive substrings in titles and saved user/assistant bodies, including Unicode content, without loading all conversation bodies into the browser or contacting Providers. A query is limited to 256 characters, 50 matching conversations, and a three-second deadline. Results contain bounded excerpts and message references for turn navigation. The active/archived filter remains explicit. A Unicode-aware SQLite scalar function avoids a schema migration and duplicate persisted text index; queries still scan eligible history, so broad searches can require refinement as history grows.

Unsent text and attachment selections remain in memory. Conversation switches, creation, and archive navigation ask before discarding a draft. Cancelling preserves it, while confirmed active-Generation navigation retains the existing cancellation-before-switch ordering. Launcher intents use the same guard, and browser navigation uses the native unload confirmation where supported. This extends the presentation-state ownership in ADR-0019 without introducing persistent draft storage.

Markdown exports project comparison dispositions at export time and group available completed answers with their originating user turn. A read-only `selected_answer` summary identifies the saved Generation, assistant message, Provider name, and model even when a Target's latest retry has changed. This adds no persisted data or mutation. Exports preserve the immutable Context Snapshot semantics in ADR-0015; a displayed Selected Answer does not imply every later Generation used it.
