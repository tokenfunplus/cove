# Add public webpage source snapshots

The composer provides an explicit **Read webpage** action. Chat retrieves the supplied public HTTP or HTTPS URL through `internal/websources`, prepares its readable text, and returns a session-bound preview token. HTTP handlers adapt the request and Browser Session identity. Retrieval runs before Generation admission and outside its lifecycle locks.

The reader uses a dedicated credential-free HTTP transport with connection-time public-address checks, validated redirects, normal TLS hostname verification, two concurrent workers, a fifteen-second request deadline, three redirects, and a four-MiB decoded response bound. HTML is decoded and processed by the pinned Go Readability parser. Plain text uses the existing text parser. Script-dependent, inaccessible, empty, unsupported, and oversized pages produce actionable errors. Webpage preview renders extracted text.

This extends ADR-0025's source formats and preview behavior. A webpage shares the four-source count and existing character limits with files. Its additive `web` metadata records original/final URLs, read time, and the downloaded content hash. A webpage snapshot identity hashes its content, provenance, extraction version, and capture time. File identities retain their original-byte hash meaning. Saved webpage bytes and sections use the existing attachment storage and atomic Batch transaction, including context snapshots, retries, branches, deletion, and exports. Source navigation retains `cove:<snapshot-id>:L<number>` links. Citation resolution establishes a saved location; interpretation remains visible for review.

Prepared sources stay in a bounded sixteen-entry memory cache. Tokens become unavailable after fifteen minutes and expired entries are removed on cache access. Removing a draft source, clearing local history, and exiting the service release prepared content. The browser aborts pending retrieval on removal, navigation, and unmount. Late completions are discarded. Generation requests resolve tokens against the Browser Session before saving sources. Repeated accepted `client_request_id` values return the existing Batch even after preview expiry or release.

The saved `input_content` supplies the same webpage text to ordinary Providers and browser-side NearAI inference. Origin website requests occur during the explicit reading action. Model requests occur when sending the question. The source preview and privacy guide disclose these destinations. NearAI verification continues to describe the inference transport and response evidence.

The API and snapshot additions fit the existing schema-21 JSON storage. Existing file records retain their representation. The frontend exposes webpage provenance in source previews and Markdown/JSON exports. Search discovery and browser rendering can subsequently supply this same source pipeline.
